# Merge train run (assembly, gate, publish, red-batch rules)

`merge-train-run.py run` is one cycle of a merge train; `merge-train.py` (queue and planner) picks the members.

1. Take the **lease** (an flock in the train state dir; one train per repo and integration branch; the OS frees it when the process dies).
2. Run the project's **preflight** hook; a non-zero exit refuses the cycle before any scratch tree is cut.
3. Plan up to the **adaptive limit** of members, **assemble** them as one tree on `train/<UTC>-<n>` (each member's *recorded* tip, regenerated by the project's hook and committed, so the tree the gate records is the tree it publishes), push it.
4. **Gate** it through `merge-to-integration.sh` (contract unchanged: exit 0 plus a `merged into` line = landed). A gate that pushed the integration branch landed the set whatever it printed afterwards: git is the proof.
5. **Publish and close out**: every member's work must be in the LANDED commit before its issue is closed with a per-member comment (naming the proof), its branch deleted under a lease on the recorded tip, and an issue closed under a newer READY reopened. The **landing proof** (`train_lib.landing_proof`) is one of `ancestor` (the tip is in the branch's history), `patch` (every commit is patch-equivalent to one there: the gate lands by rebase) or `content` (merging the tip into the branch adds nothing, `git merge-tree`: the gate squashes a branch that holds merge commits, so a train lands as ONE commit no member tip is an ancestor of). The queue's `on-master` state and the newer-READY reopen read the same proof, so a squash-landed member is never planned again. Then the project's **`landed` hook** runs once per landing (an upstream sync, a drift check), with `AUTOCODER_TRAIN_LANDED`, `AUTOCODER_TRAIN_BASE`, `AUTOCODER_TRAIN_BRANCH`, `AUTOCODER_TRAIN_INTEGRATION`, `AUTOCODER_TRAIN_MEMBERS` (the proven members, `issue<TAB>tip<TAB>branch` rows) and `AUTOCODER_TRAIN_UNLANDED` (the rest) in its environment; it cannot unland anything, a failure is logged and reported.

## Red-batch rules

| Failure | What happens |
|---|---|
| Names members (a path only some members' diffs touch, or the project's `attribute` hook) | those members are returned to their owners with the log; the **remaining members are re-gated as a new set** |
| Names nobody | bisect: gate the first half; green lands at once and the other half is red by inference (it splits without a gate); red splits again and the other half is gated; one member left red is returned with the log |
| `::error::<stage>: INFRASTRUCTURE ...` | the same set is re-gated once; nobody is dropped, held out or bisected; a second one ends the cycle with everyone back in the queue, unfaulted |
| Regeneration or scratch fault | nobody is blamed; nothing is gated |
| Gate budget (`maxGates` after the first) spent | undecided members stay in the queue, unfaulted |

One bad member of eight: a bad member in the last half-chain costs three further gates while seven land; a bad member in the first costs more (a red gate lands nothing, so the good members behind it need green gates of their own), bounded by twice the depth. Two gates at once (one per half) is not implemented; the halves gate one after the other.

**Member accounting** is `cycle.json` plus git, never the tracker. A tracker call that fails is queued in `pending.json` and retried at the next cycle's start (`status` shows the count); it cannot change who is in a set, who landed or who was returned. A cycle left by a dead process is reconciled against git at the next start: landed members are closed out, the rest requeued, the train branch deleted.

**Adaptive size**: `batch.json` holds the limit (start `batchStart` 8, +1 after a green first gate up to `batchMax`, halved after a red one down to `batchMin`; an infrastructure red or abort leaves it) and the last 50 batches.

## `train` keys read here (the rest are in README.md "Merge trains")

`gate` (command template; `{train} {sha} {issue} {integration} {test_cmd}` are shell-quoted; default `merge-to-integration.sh --feature ... --issue {gateIssue} ...`), `gateIssue`, `testCmd`, `batchStart`, `batchMin`, `batchMax`, `maxGates`, `infraRegates` (1), `infraPattern`, `reportIssue` (batch-level notes; empty = member issues only), `swarm` (prefix of every tracker write), `timingsCmd` (default: `landing-timings.py` beside these scripts when present), `gateLogDir`, `hooks.preflight`, `hooks.regenerate` (run in the scratch; `AUTOCODER_TRAIN_BASE` is the base sha), `hooks.attribute` (stdin: the failure text; `AUTOCODER_TRAIN_MEMBERS`: `issue<TAB>tip` rows; prints the named issues), `hooks.landed` (run in the repo after a landing; see step 5).

Timing rows (`batched`, `landed`, `returned` per member; one `batch` row per gate) go through `landing-timings.py`. Exit codes: 0 cycle ran or nothing to train, 1 refused (lease, preflight), 2 planner or scratch fault, 3 environment error. Tests: `tests/test_merge_train_run.py`.
