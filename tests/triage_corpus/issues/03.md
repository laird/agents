# Research workflow fails on every engagement with > 3 pillars

Since the v2.13 deploy, any engagement scoped with more than 3 pillars fails
partway through research. The Temporal workflow reports

```
ApplicationError: pillar_workflow timed out waiting for synthesis activity
```

on the 4th pillar onward. The first 3 pillars complete normally.

Affected: ~40% of active engagements (anyone running a full CDD scope, which
is 6 pillars by default). The remaining 60% on narrowed scopes are
unaffected.

Workaround we've found: manually edit the engagement scope down to 3
pillars, run research, then re-add the remaining pillars and re-run. This
is fiddly, takes ~15 minutes per engagement, and loses the cross-pillar
synthesis. Customers are complaining loudly — this is the core feature and
it's broken for the majority use case.

No data loss, but the product is effectively unusable at default scope.
