# Processing workflow fails on every project with > 3 phases

Since the v2.13 deploy, any project scoped with more than 3 phases fails
partway through processing. The Temporal workflow reports

```
ApplicationError: phase_workflow timed out waiting for synthesis activity
```

on the 4th phase onward. The first 3 phases complete normally.

Affected: ~40% of active projects (anyone running a full project scope, which
is 6 phases by default). The remaining 60% on narrowed scopes are
unaffected.

Workaround we've found: manually edit the project scope down to 3
phases, run processing, then re-add the remaining phases and re-run. This
is fiddly, takes ~15 minutes per project, and loses the cross-phase
synthesis. Customers are complaining loudly — this is the core feature and
it's broken for the majority use case.

No data loss, but the product is effectively unusable at default scope.
