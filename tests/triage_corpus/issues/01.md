# Auth bypass: any string accepted as valid session token on /admin routes

After deploying v2.14.0 we discovered that the session-token check on the
`/admin/*` routes is short-circuiting and returning `authenticated=true` for
**any non-empty string** passed in the `X-Session` header. Verified on
production: I can hit `/admin/users` with `X-Session: foo` and get the full
user list back, including email addresses and hashed passwords.

Reproduction:

```
curl -H "X-Session: anything" https://app.example.com/admin/users
```

This is an active exploit path on prod right now. We have not yet seen
evidence of exploitation in logs, but the window has been open for ~6 hours
since the v2.14.0 rollout. Need an immediate fix + rotate all admin
sessions.
