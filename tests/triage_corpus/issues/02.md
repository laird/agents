# Production down: all writes to engagements table failing with FK violation

Production is fully down for write traffic. Every `POST /api/v1/engagements`
and `PUT /api/v1/engagements/:id` is returning 500 with the underlying
Postgres error:

```
ERROR: insert or update on table "engagements" violates foreign key
constraint "engagements_owner_id_fkey"
DETAIL: Key (owner_id)=(...) is not present in table "users".
```

This started ~20 minutes ago, immediately after migration `0147_drop_users_legacy`
ran. It looks like the migration dropped rows from `users` that engagements
still reference. Existing rows are also at risk — any cascade delete will
corrupt the engagement history.

No workaround. Customers cannot create or update engagements. We need to
roll back the migration and restore the users rows from the pre-migration
snapshot before any more damage accumulates.
