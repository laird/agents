# Engagement list sort-by-date is reversed when filter is applied

When you load the engagements page with no filter, the list is sorted
newest-first, which is correct. As soon as you apply any filter (status,
owner, tag), the sort flips to oldest-first. Removing the filter restores
the correct order.

This is a bug in the list query — the filtered branch is using
`ORDER BY created_at ASC` instead of `DESC`. Single-line fix probably.

Impact: some users (those who use filters, maybe 30% based on product
analytics) see a confusing ordering, but the data is correct and they
can re-sort by clicking the "Date" column header, which gives them the
expected newest-first view. So there's a one-click workaround.

Not blocking anyone, just annoying and looks unpolished.
